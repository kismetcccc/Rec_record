# 共交互图补全的供体相关性、冷启动支持与污染传播

共同基础：缺失内容经物品关系传递。以下三项分别是**同质性收益的模型依赖、结构支持不足、供体内容受损**，成因不同，保留子项；不合成泛泛的“补全鲁棒性”。

## P01 图同质性不能作为跨下游模型通用的补全收益保证
- **问题与条件**：使用共交互图补全时，供体相关性与下游收益并非同一件事；更高图同质性不能跨推荐器统一保证更高效果。
- **仍成立的证据**：GMI VI-D/Fig.4 显示同质性与效果的关系依赖 VBPR/MGCN 等下游模型，作者保留对这种关系的理解问题。
- **已处理的背景，不另计残余**：GRE-MC §3.3、§5.3.5/Fig.9 显示其检索供体比局部近邻更相关，已缓解近邻语义不足；不据此称 GRE-MC 仍有相同缺陷。
- **已处理/剩余**：GRE-MC 已用全图检索缓解局部近邻问题，不能把旧动机说成其未解决缺陷；GMI 的图同质性收益不是对所有模型单调成立。GRE-MC 至少保留一个模态的设定仅是双缺失未验证边界，不算双缺失失败。
- **类型**：作者明确指出、实验支持。范围限定所测供体/模型，不推断全部行为边无用。
- **代码**：GMI `impute.py::get_item_item` 从 TRAIN 共交互构图，`neigh_mean` 聚合；GRE-MC 未找到可核验官方实现。

## P02 冷启动或极少交互使补全缺乏结构支持
- **问题与条件**：内容缺失且交互稀少时，目标在共交互图中支持不足，补全能力受限。
- **证据**：GMI IV-D 明确承认该条件。未报告可引用的冷启动跌幅。
- **已处理/剩余**：四种训练免费方法可传播已有内容，但不能消除其对交互图支持的依赖。
- **类型**：作者明确指出；代码观察印证依赖，不是冷启动失败率的实测。
- **代码**：同一 `get_item_item`，不得仅凭没有“冷启动模块”推断缺陷。

## P03 已观测供体受污染时，补全可传播错误内容
- **问题与条件**：供体已有特征但不可靠，补全将污染沿关系送入缺失物品。
- **证据**：GMI IV-D 明确指出噪声嵌入可能被传播。
- **已处理/剩余**：补全解决缺值，不保证错误供体可恢复为可靠内容；不能把作者风险声明当作本轮噪声注入实验。
- **类型**：作者明确指出；静态源码只定位传播路径。
- **代码**：`impute.py` L246–269 的迭代传播。
